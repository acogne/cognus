1. Vue d'ensemble

Cognus est un dashboard web de validation et de publication de podcasts, conçu pour les équipes de rédaction du groupe radio. Il centralise en un seul endroit les épisodes de 4 stations (One FM, Radio Lac, LFM, Rouge), permet de les valider, de les modifier et de les envoyer vers WordPress via Make.com.

L'application est un fichier HTML unique hébergé sur GitHub Pages, sans serveur ni base de données. Toutes les données sont stockées dans un Google Sheet partagé.

2. Architecture technique

Stack

  • Frontend : HTML/CSS/JavaScript pur (pas de framework), un seul fichier index.html
  • Authentification : Google OAuth 2.0 via Google Identity Services (GIS)
  • Stockage des données : Google Sheets API v4
  • Automatisation : Make.com (webhooks + scénarios)
  • Publication : WordPress (via Make.com)
  • Hébergement : GitHub Pages (acogne.github.io/cognus)
  • PWA : Service Worker + manifest.json pour installation sur mobile/Chrome

Identifiants clés

ConstanteOùDescription
CLIENT_IDindex.htmlGoogle OAuth 2.0 Client ID (Google Cloud Console) — sans danger en public
SHEET_IDindex.htmlIdentifiant du Google Sheet principal
WEBHOOK_*GitHub SecretsURLs Make.com stockées de façon chiffrée, jamais visibles dans le code source

Protection des webhooks

Les URLs des webhooks Make.com sont stockées dans les GitHub Secrets du dépôt (Settings → Secrets and variables → Actions). Un workflow GitHub Actions (.github/workflows/deploy.yml) les injecte dans index.html à chaque déploiement. Le code source public ne contient que des placeholders (%%WEBHOOK_ONEFM%% etc.).

Le dépôt peut rester public — les webhooks sont protégés par les secrets GitHub et ne sont jamais exposés dans le code source visible.

4. Intégration Make.com → WordPress

Principe général

Chaque station possède un scénario Make.com indépendant. Le scénario est déclenché par un webhook HTTP que Cognus envoie au moment de la publication.

URLs des webhooks

StationWebhook Make.com
One FMStocké dans GitHub Secret WEBHOOK_ONEFM
Radio LacStocké dans GitHub Secret WEBHOOK_LAC
LFMStocké dans GitHub Secret WEBHOOK_LFM
RougeStocké dans GitHub Secret WEBHOOK_ROUGE

Données envoyées par Cognus (payload JSON)

{ "titre": "...", "resume": "HTML ou texte", "excerpt": "...", "transcript": "...", "dateCreation": "..." }

Ce que fait le scénario Make.com

  1. Réception du webhook avec les données de l'épisode
  2. Création ou mise à jour d'un article dans WordPress (titre, contenu, excerpt)
  3. En cas de succès : Make.com écrit "Success" dans la colonne G du Google Sheet, à la ligne correspondante

Confirmation WordPress dans Cognus

Après avoir cliqué "Publier", Cognus démarre un polling toutes les 5 secondes de la colonne G. Dès que "Success" est détecté :

  • L'épisode passe en statut "Publié" (colonne F ← "Publié")
  • Le badge ✓ WordPress s'affiche sur la carte
  • La carte se déplace dans l'onglet "Publiés"
⚠ Si Make.com ne répond pas dans les 2 minutes (24 tentatives × 5 s), le polling s'arrête et un message d'erreur s'affiche. La colonne G reste vide et l'épisode reste en "À vérifier".

5. Flux complet de publication

Make.com remplit le Sheet → Cognus détecte le nouvel épisode (refresh 30s) → Équipe vérifie & modifie si besoin → Clic "Publier" → webhook Make.com → Make.com publie sur WordPress → Make.com écrit "Success" col. G → Cognus confirme → statut "Publié"

Republication

Si un épisode déjà publié est modifié via Cognus, un bouton "Republier" apparaît. Le flux est identique à la première publication. L'ancien article WordPress est mis à jour (selon la configuration du scénario Make.com).

Règle de sécurité

Il est impossible de cliquer sur "Publier" tant qu'une publication est déjà en cours (badge ⏳ visible sur une autre carte). Ceci évite les publications en doublon.

Depuis la page Admin → section "Utilisateurs autorisés" → saisir l'adresse e-mail Google → cocher "Admin" si nécessaire → cliquer "Ajouter".

8. Page d'administration

Accessible uniquement aux administrateurs via le bouton ⚙ Admin sur le hub.

Fonctionnalités

  • Gestion des utilisateurs : ajout, suppression, et bascule du rôle Admin (★ Admin / ☆ Standard) pour chaque utilisateur inscrit
  • Statistiques par station : épisodes publiés, modifiés avant/après publication, moyenne de modifications, temps de réaction moyen création → publication
  • Classement global : personnes ayant publié le plus d'épisodes toutes stations confondues
  • Documentation : ce document (bouton 📖 dans le header)
Les statistiques "modifications" et "publishedBy" ne sont alimentées qu'à partir de la mise en service de Cognus v2 (colonnes K et L du Sheet). Les épisodes antérieurs affichent "—" pour ces métriques.

9. Déploiement

GitHub Pages + GitHub Actions

L'application est hébergée sur GitHub Pages à l'adresse https://acogne.github.io/cognus/. Le déploiement est automatisé via GitHub Actions : chaque upload sur la branche main déclenche le workflow qui injecte les secrets et déploie le site.

Processus de mise à jour

  1. Modifier index.html localement (ou directement sur GitHub)
  2. Uploader / commiter sur la branche main
  3. Le workflow .github/workflows/deploy.yml se déclenche automatiquement
  4. Les placeholders %%WEBHOOK_*%% sont remplacés par les vraies URLs depuis les secrets
  5. Le site est déployé — visible en quelques secondes

Fichiers du dépôt

FichierRôle
index.htmlApplication complète — contient des placeholders pour les webhooks
.github/workflows/deploy.ymlWorkflow GitHub Actions : injection des secrets + déploiement

Picto Cognus.pngLogo Cognus (favicon + header)
One FM.png / Radio Lac.png / LFM.png / Rouge.pngLogos des stations

GitHub Secrets requis

Ces 4 secrets doivent être configurés dans Settings → Secrets and variables → Actions du dépôt GitHub :

SecretDescription
WEBHOOK_ONEFMURL du webhook Make.com — One FM
WEBHOOK_LACURL du webhook Make.com — Radio Lac
WEBHOOK_LFMURL du webhook Make.com — LFM

Google Cloud Console

L'authentification Google OAuth nécessite que le domaine acogne.github.io soit déclaré dans les Origines JavaScript autorisées de l'application OAuth dans Google Cloud Console → APIs & Services → Identifiants.

10. Maintenance et points d'attention

Si Make.com ne publie plus

  1. Vérifier que le scénario Make.com de la station est bien actif
  2. Vérifier que l'URL du webhook dans Cognus correspond au webhook actuel dans Make.com
  3. Tester le webhook manuellement depuis Make.com
  4. Vérifier les logs d'exécution Make.com pour identifier l'erreur WordPress

Si la connexion Google ne fonctionne plus

  1. Vérifier que le CLIENT_ID dans index.html est valide (Google Cloud Console)
  2. Vérifier que acogne.github.io est dans les origines autorisées
  3. Vérifier que les APIs "Google Sheets API" et "OAuth 2.0" sont activées dans le projet GCP

Si le Sheet ne se charge pas

  1. Vérifier que le SHEET_ID dans index.html est correct
  2. Vérifier que le compte Google connecté a accès en lecture/écriture au Sheet
  3. Vérifier que les noms d'onglets correspondent exactement : "One FM", "Radio Lac", "LFM", "Rouge", "Cognus_Config"

Mise à jour des webhooks Make.com

Si les URLs des webhooks changent, mettre à jour les GitHub Secrets (pas le code source) :

  1. Aller sur GitHub → Settings → Secrets and variables → Actions
  2. Cliquer sur le secret à modifier (ex. WEBHOOK_ONEFM) → ✏️
  3. Coller la nouvelle URL → "Update secret"
  4. Déclencher un nouveau déploiement en faisant un commit quelconque sur main

Ajout d'une 5e station

  1. Créer un nouvel onglet dans le Google Sheet avec la même structure de colonnes A→M
  2. Ajouter la station dans l'objet STATIONS dans index.html
  3. Ajouter un nouveau secret GitHub pour le webhook
  4. Ajouter le sed correspondant dans .github/workflows/deploy.yml
  5. Ajouter la carte station dans le HTML du hub
⚠ Après toute modification de index.html, uploader sur GitHub et attendre que le workflow Actions termine (onglet Actions → job vert ✅). Le Service Worker peut mettre en cache l'ancienne version — forcer un rechargement complet (Ctrl+Shift+R) si nécessaire.
